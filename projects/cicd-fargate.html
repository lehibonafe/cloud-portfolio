ECS Fargate CI/CD Design

Designed a pipeline to build Docker images, push them to Amazon ECR, and roll out ECS service updates.

DockerECRECSFargate

Overview

Fargate removes the need to manage EC2 instances for containers. This design covers repeatable image builds and controlled ECS service updates with health checks before traffic shifts.

Pipeline stages

  • Build — docker build with immutable tags (git sha + latest)
  • Push — authenticate to ECR, push image layers
  • Deploy — register new task definition, update ECS service, wait for steady state

ECS configuration

A proposed task definition specifies CPU, memory, container image URI, CloudWatch logging, and environment secrets from SSM or Secrets Manager. The service design uses a target group behind an ALB for HTTP health checks.

Rollback strategy

Keep previous task definition revisions. If deployment fails health checks, ECS circuit breaker or a manual rollback reverts to the last known-good revision without rebuilding the image.

Security

  • Use OIDC for AWS credentials instead of long-lived keys in CI
  • Enable ECR image scanning on push
  • Separate task and execution roles for least privilege
