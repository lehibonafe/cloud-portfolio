AWS Static Portfolio Deployment

Automated S3 uploads and CloudFront cache invalidation with GitHub Actions, using Route 53 to route traffic to the site.

S3CloudFrontRoute 53GitHub Actions

Overview

This project hosts a fully static site on AWS with no application servers. Assets live in S3, CloudFront caches and serves them at the edge, and GitHub Actions syncs files and invalidates the cache on pushes to main.

Architecture

  • S3 — private bucket; objects served only via CloudFront OAI/OAC
  • CloudFront — HTTPS delivery and a viewer-request function for clean project URLs
  • DynamoDB — serverless database, count number of visits
  • Route 53 — alias record pointing the domain to the CloudFront distribution
  • ACM — TLS certificate in us-east-1 for CloudFront
  • GitHub Actions — sync aws s3 sync and cloudfront create-invalidation

Deployment flow

git push → Actions checkout → sync to S3 → invalidate CloudFront cache

Invalidation keeps visitors from seeing stale HTML or assets after a deploy. For a portfolio, invalidating /* is simple; larger sites often target specific paths.

Key decisions

  • Block all public S3 access; CloudFront is the only read path
  • Versioned bucket optional for rollback; lifecycle rules control cost
  • Use OIDC to grant GitHub Actions temporary AWS deployment credentials

Outcomes

Low operational overhead, predictable cost, and a deploy pipeline that matches how the site is actually built — static files only.
